# 進捗報告

最終更新 2026年10月29日。詳細な確認結果は `docs/TEST_REPORT.md` を正本とする。

## やったこと

### 実装（10月21日まで）

- 承認済み要件を基に、Next.js・TypeScript・Tailwindの基盤を作成した。
- Supabase用のDB・RLS・ジョブ排他取得・AI上限・データ削除のSQLを作成した。
- LINE署名検証、Echo、Claudeによる根拠FAQ選択、有人引き継ぎ、個人LINE通知、停止・再開を実装した。
- スマホ対応のFAQ・メニュー編集、問い合わせ・会話一覧を実装した。
- 一斉配信は承認済みの既存公式LINE画面を使う方針を維持した。
- API接続なしのデモ、セットアップ手順、オーナー向けマニュアルを用意した。

### 実接続と公開（10月21日〜29日）

- テスト用LINE公式アカウント・Supabase（シドニー）・Claude APIを接続し、Vercel Hobbyで公開した（`https://salon-line-bot-three.vercel.app`）。関数はSupabaseに近い `syd1` で動かす。
- 本人のLINEだけを対象に（`TEST_USER_ONLY=true`）、受け入れ確認の項目を実LINEで1回ずつ確認した。
  - F01：FAQ言い換え15件はすべて承認済みFAQの原文で回答。範囲外5件はすべて作り話なしで引き継いだ。
  - F02：予約希望と個別判断（髪の状態を伝えた組み合わせの質問）を引き継ぎ、オーナー通知は各1回。管理画面で元の質問を確認し、対応済みにした。
  - F03：スマホで料金を変更し、新しい質問の回答に反映された。
  - F04：公式LINEの既存の配信画面から、本人1人だけにテスト配信した。
  - F05：有人対応中は返信・通知を止め、管理画面から再開した。
  - 不正な署名と未ログインの管理APIは401で拒否。日次Cronの自動実行を1回確認した。
- 組み合わせFAQの言い換えが引き継ぎになったため、FAQをオーナー承認済みの文面に更新し、AIへの指示に「一般方針はFAQで回答、本人の髪の判断は引き継ぐ」を追加した（10月24日）。修正後は、一般の質問3件がFAQで回答され、個別判断の1件は引き継がれた。
- 自動テストは48件成功（10月28日）。型チェックと本番用ビルドも成功。

## 練習課題として残っていること

受け入れ確認（`docs/requirements.md`）の項目は、すべて実LINEで1回以上確認した。以下は確認の深さを増やす項目で、`docs/TEST_REPORT.md` の「未確認の項目」に対応する。

- 通知失敗後の再試行（管理画面の再試行、同じretry keyでの再送）
- ログイン済みの非オーナーが、実環境でデータを読めず変更できないこと（自動テストでは確認済み）
- 同じイベントがLINEから再送されたときに、通知が重複しないこと（自動テストでは確認済み）
- Cronの連日の自動実行と、保持期限削除で30日を超えたデータが実際に削除されること（削除対象は11月21日以降に初めて生じる）
- 受信時の拾い直しの実環境での動作、FAQのバックアップと復旧
- 実スマホ（Chrome・Safari）での画面幅・タップ・キーボード・読み上げ
- 公式LINEの自動応答との二重返信を狙った確認

## 実店舗で使う前に必要なこと

- 店舗の正式な営業時間・料金・住所・駐車場・併用施術方針・予約案内先を受け取り、オーナーの承認を得てからFAQとメニューを置き換え、全FAQをテストLINEで確認する（現在はすべて練習用サンプル）。
- 月額上限・LINEの契約プラン・導入日・30日保存・個人LINE通知の運用について合意する（`docs/requirements.md` の「承認前に追加確認すること」）。
- 店舗名義でLINE公式アカウント・Supabase・Vercel・Claude APIを契約し、請求設定と利用上限を確認する。
- Vercelを商用利用できるProに切り替え、Cronを1分ごとに戻す。Cronの失敗監視を用意する。
- `TEST_USER_ONLY` を外し、テスト用アカウントと実顧客用アカウントを分けて切り替える。
- お客様向けの利用案内（質問がClaude APIへ送られること、保存期間）を公開する。
- オーナーへの操作説明（管理画面・公式LINEでの返信・月2回の配信手順）を行い、導入前1週間の対応件数・所要時間を記録する。
- 3秒以内の最終返信は保証しない（今回の実測は、DB記録で2〜3秒、体感で約10秒）。
